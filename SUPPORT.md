# Support and security

Self-hosting operators own their database, private files, secrets, backups and
provider accounts. Read [INSTALL.md](INSTALL.md) and [OPERATIONS.md](OPERATIONS.md)
first. Paid installation/configuration is an external service, not a product
subscription or managed-hosting feature.

For a reproducible problem, report package version/source revision from health,
platform, provider mode, the failed public command, safe error/status, expected
behavior and a minimal synthetic reproduction. Keep raw logs private; remove
cookies, login links, personal details, invoice contents, tokens, credentials and
storage keys. Never upload an environment or backup file to an issue.

Use [GitHub issues](https://github.com/DB-Conneely/Yinsen/issues) for ordinary bugs.
Report security issues through [GitHub private vulnerability reporting](https://github.com/DB-Conneely/Yinsen/security/advisories/new).
Do not publish exploit details or private customer data in an issue. A response-time or commercial
support guarantee is not implied by the MIT license.

Linux amd64/local Docker is qualified. Optional R2, Resend and direct Stripe have
source-bound nonproduction evidence with the limits in [INSTALL.md](INSTALL.md).
Other S3 vendors/architectures, multi-replica operation and future-release rollback
are not claimed verified. Inspect the actual GitHub run/release for qualification
or publication evidence; production and website integration need proof on the
specific installation.
