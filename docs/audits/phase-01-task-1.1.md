## A11-01 — Medium — Required HSTS policy is absent

**Classification:** actual configuration/security-contract defect, reproduced at the installed response boundary; not a missing provider resource.

**PROBLEM**

The retained original infrastructure requirement explicitly specifies `Strict-Transport-Security: max-age=31536000` (`docs/legacy/implementation-original.md:318`). No active contract reconciliation removes it. Current `next.config.ts:13` emits five security headers but no HSTS policy. The fresh ordinary production response from `http://localhost:3012/api/health` likewise has no `strict-transport-security` header; its complete redacted headers are retained in `.local/audit-11/proof.json`, entry `health`. The same response does contain the configured CSP, frame, MIME, referrer and permissions policies, so this is an omission in the actual shared header path, not an unexecuted configuration file.

The documented internet-facing installation supplies an owner-selected HTTPS reverse proxy (`docs/operator.md`, Docker Compose section), but neither an implemented proxy configuration nor an instruction assigns HSTS to that boundary. Consequently a TLS proxy that simply forwards the app's responses does not provide the retained browser HTTPS-only policy. HTTPS origin validation and Secure cookies do not themselves establish that policy. HSTS instructs browsers to retain HTTPS-only access after receiving it securely; this is described in the pinned Next guide, `node_modules/next/dist/docs/01-app/03-api-reference/05-config/01-next-config-js/headers.md:523`, and [RFC 6797](https://www.rfc-editor.org/rfc/rfc6797.html). No public HTTPS installation, browser downgrade attack or credential disclosure was exercised or claimed.

The current header unit test checks only `X-Frame-Options`; the installed HTTP test checks frame/MIME headers but not HSTS. Both pass with this omission (`tests/foundation.test.ts:130`, `tests/http.ts:6`).

**PROPOSED SOLUTION**

The smallest correction appears to be adding the retained `Strict-Transport-Security: max-age=31536000` value to the existing global Next header list and extending its meaningful installed-response regression. Re-exercise ordinary source and container responses after rebuilding the affected configuration. Keep this to the agreed host policy; `includeSubDomains` and preload would add promises outside the retained requirement. Document the HTTPS termination boundary and the distinction between observing the emitted header locally and browser enforcement over HTTPS. This proposal is advisory; the fresh patch owner should independently confirm it.
